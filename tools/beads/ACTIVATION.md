# Native Beads activation

The installed immutable supervisor owns the HTTP and Dolt children. `inventory`, `checkpoint`, `restore`, and `verify` emit the shared `schema_version: 1` target contract. Native controls use an owned private Unix endpoint under the service state directory; long state paths use a private UID directory in `/tmp` keyed by the canonical home. Endpoint removal checks the bound inode, preserving replacements and unexpected files.

The target identifies the loaded controller release, its runtime manifest, and both child executable images. Linux binds children through `/proc/PID/exe`; macOS binds the mapped executable vnode to the immutable installed file. Mutable development scripts and legacy controllers remain usable but report unknown activation identity and refuse a managed checkpoint. Readiness comes from the configured database-backed HTTP endpoint and is independent of artifact identity.

Checkpoint requests carry the observed native process tuple and operation UUID. The supervisor refuses a changed incarnation, unknown image, competing update, or active history operation before cancellation. It then fences history admission, requests one graceful termination of HTTP, observes acknowledgement, and terminates Dolt only after HTTP exit. A late child exit is observed without repeating its signal. After both children exit, the native checkpoint is confirmed while the supervisor remains available for verification. Interrupted effects remain unknown and must never be replayed.

Managed service definitions restart after failure and carry a startup retirement-policy marker. An unknown policy refuses checkpointing before cancellation. Native `restart` requires the same confirmed checkpoint and verifies the service manager's MainPID. It requests irreversible native retirement, then observes normal supervisor exit and no manager respawn before changing the OS job. A missing native owner or changed service registration returns 3. No update path asks the OS manager to terminate a live native owner or escalates to forced termination. The `retire` command exposes this guarded native normal-exit request. The driver retains checkpoint and process evidence when replacement or verification is incomplete. `restore` observes a newly running selected supervisor; it cannot reverse an old drained supervisor or replay its interrupted HTTP operations.

Installation stages an immutable controller release and pinned binaries without changing task data or the existing trial TOML. Installation receipts establish staged input hashes; running-version acceptance additionally requires native controller and child bindings plus readiness. Backup and task-history synchronization remain explicit operations outside runtime maintenance.
