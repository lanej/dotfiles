Tasks adds an overview and workspace context panel for work managed through ordinary Pi conversations. Every task has a persistent worker conversation that you can open directly, with its desired outcome, success criteria, approach, progress, evidence, blockers and next action. An ordinary Pi manager can create drafts, start specified tasks, discover conversations for your selection, and apply bulk controls.

Each execution host owns its durable SQLite records. The overview aggregates registered authenticated Paseo hosts and preserves the last observation when a host is unavailable. Host-qualified identities bind actions to the intended worker. Pausing and archiving stop task-service dispatch at a turn boundary; queued feedback remains durable. Task completion is reported separately from agent activity.

Workers created or adopted by a manager report completion, evidence, decisions and blockers back to that coordinator conversation. Reports survive closed app windows, host disconnects and service restarts. Admission waits for both conversations to be observed at a turn boundary and preserves the worker's identity. Paseo dispatches admitted messages later; input or an archive arriving in that interval can still be affected by its native queue. The task panel opens the coordinator directly; its report inbox distinguishes durable host receipt, queued delivery and confirmation in conversation history.

This plugin requires Node 24, official Paseo 0.15.1 clients and daemons, Pi, Treehouse for new coding workers, and the shared Paseo question and router extensions in this dotfiles checkout. New coding tasks lease an isolated checkout at the specified base and retain its lease identity; adopted work keeps its existing checkout and ownership. The default is Sonnet 5.5 with adaptive medium thinking through the existing Bedrock router's Anthropic Messages route. GitHub feedback requires the host's existing GitHub authentication. Connected hosts need their own plugin installation and registered Paseo connections.

The backend reads and writes task records, leases Treehouse checkouts, creates Paseo workspaces and Pi conversations, polls linked GitHub issues and PRs, and submits worker-directed replies to their source discussions. For open PRs it sends new failed checks and merge conflicts to the existing worker for repair, then slows polling to watch review comments. Repairs and review replies stay in that same conversation while the manager is closed. Watch phases appear separately from agent activity. Pausing preserves queued input; archiving stops polling and retains the checkout. It preserves uncertain delivery and submission outcomes for reconciliation. Workers can change their approach and propose a changed outcome; a person accepts brief proposals in the panel. There is no automatic merge operation.

Firstmate migration inventories sessions, checkouts, links and pending feedback. Activation requires the old recorded worker, captain and supervision to be stopped. It archives the old metadata, imports the original Pi session through Paseo, verifies the session and checkout, then resumes feedback delivery. Existing worktrees and their leases are retained. Verify session import through the official entrypoint before transferring live work, then finish live rollout acceptance with direct conversation entry, source-thread feedback, and mobile reconnect while a worker continues.
