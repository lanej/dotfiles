# Capture a breakthrough

Use the supplied description and established conversation evidence to document what worked and when it applies. Ask only about information needed to distinguish the insight from an unsupported guess. Do not invent measurements, code, causal explanations, or claimed savings.

Write `breakthroughs/YYYY-MM-DD-<brief-name>.md` in the project, creating the directory when needed. If that name exists for another insight, choose a unique suffix; do not overwrite it. When explicitly updating an existing record, preserve useful prior evidence and identify the correction.

Include the applicable information:

- Title, date, relevant tags, and a one-line summary.
- The problem and concrete evidence of the previous behavior.
- The insight and minimal implementation example when one is available.
- Observed impact, with before/after metrics only when actually measured and with their sources/conditions.
- The reusable pattern: when it applies, limitations, and what would contradict the conclusion.
- Related files, sources, issues, and any corresponding dead-end record.

Update `breakthroughs/INDEX.md` with a dated title, one-line summary, and relative link. Preserve existing entries and avoid duplicate links when updating the same record. Check that the saved record and index link are readable. Report their paths and any material evidence gap.

An invocation authorizes this project documentation, not a global memory write, commit, publication, message, or implementation task. Under write restrictions, return a draft and state that the files were not saved.
