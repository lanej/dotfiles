# Local worker acceptance

Build with `bun run build:aot` first to exercise the compiled driver through the same `scripts/pi-driver` entry point. In a checkout with a build, `PI_DRIVER_USE_SOURCE=1` selects the source path.

From the package root, run `bun run test:local` after installing package dependencies and the native `zellij` and `worktree` commands. The harness reads pinned Beads and Dolt binaries from `~/.local/share/beads-service/runtime.json`; set both `PI_DRIVER_NATIVE_BD` and `PI_DRIVER_NATIVE_DOLT` to use explicit binaries instead. `PI_DRIVER_NATIVE_PYTHON` selects the Python interpreter when `python3` is unsuitable.

The fixture creates its own Dolt server, Beads HTTP service, Git repository, managed worktrees, Pi agent directory, journal and Zellij session. It makes Paseo unavailable and guards against driver subprocess calls to either Paseo or Zellij. Zellij itself runs as the native terminal under test. The driver uses the Unix socket for pane launch, discovery, and focus. It preserves existing services and terminal sessions. A deterministic loopback OpenAI-compatible provider lets the real interactive Pi acknowledge the accepted bead context and subsequent guidance in the same worker pane. The successful case invokes the real `task_submit_result` tool; failure cases use the native `/task-submit` command. This exercises native Pi input, extension dispatch, tool execution and SDK streaming; it does not assess an external model's reasoning or credentials.

The direct-worker cases exercise successful verification and confirmed closure, verifier exit code 7 without closure, and an edited brief that requires review without closure. The launcher retains focus when each worker starts. Repeating the successful case's identical start must focus the same registered pane and retain its attempt, process and managed checkout without creating another allocation. Each case exits Pi and reads the task and persisted verification with a fresh driver process. Native manager protection is finished and the clean fixture worktrees are explicitly pruned after the owned session exits.

Set `PI_DRIVER_ACCEPTANCE_OUTPUT` to a task-owned directory to retain each run in its own subdirectory containing `report.json`, per-case native pane text, raw terminal ANSI and the actual loopback provider requests. Without that setting all fixture artifacts are disposable; the JSON report is printed to standard output. Provider requests contain the fixture's prompts and accepted task context, so use only disposable task data.

`bun run generate:zellij` regenerates the TypeScript bindings from the package’s `zellij-revision` pin. `bun run check:zellij` checks for drift. Set `ZELLIJ_PROTO_CHECKOUT` to a local Zellij Git checkout containing that revision to run either command without fetching schemas.

The lead case drafts an optional child graph, opens the terminal diff viewer, and waits for the operator’s approval before creating child beads. Local verification of the lead retains the parent’s in-progress state. Set `PI_DRIVER_ACCEPTANCE_CASE=lead-plan` to run this case independently.

Set `PI_DRIVER_ACCEPTANCE_CASE=socrates` to exercise the native question dialog, Escape and resume, selected and typed answers, stale answer rejection after a Beads edit, specification freeze, approval, verification and reopening the original lead. Run `PI_DRIVER_ACCEPTANCE_CASE=socrates-ready` to verify that a complete brief reaches freeze without opening a dialog. The case then uses a controlled Octo CLI receipt to exercise the native inbox, close the Beads task, prune the checkout, and verify the archived transcript. Octo’s own acceptance suite covers its real CLI and coordinator with a controlled GitHub provider.
