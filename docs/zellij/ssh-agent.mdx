---
title: "SSH and forwarded agents"
description: "Connect to remote sessions and keep forwarded authentication working after reconnecting."
---

From a local Zellij session, run:

```sh
zssh myhost
zssh myhost work
```

The first command opens a tab for `myhost` and attaches to or creates its `main` session. The second chooses `work`. Both hosts need the managed dotfiles setup, including Zellij and the remote attach helper. Outside Zellij, `zssh` connects in the current terminal.

Inside Zellij, `zssh` uses ordinary SSH to avoid Kitty's terminal bootstrap. Outside Zellij, it uses Kitty's SSH kitten when available, otherwise ordinary SSH.

**Ctrl-f u** returns keyboard control to the containing local session. **Ctrl-f i** enters the remote one again. Disconnecting leaves the remote programs running.

## Forward an SSH agent

Enable forwarding for your remote host in your local SSH configuration, or connect with `ssh -A HOST`. On the remote host, install the managed shell configuration and native helper with `make zsh-config zellij-helpers`. Reconnect after installation. Setup preserves an existing custom `~/.ssh/rc`; if it reports one, add `"$HOME/.local/bin/zellij-agent" publish-login` to that hook. Automatic publication requires SSH user rc hooks to be enabled by the server and your authorized key.

Remote shells export `SSH_AUTH_SOCK=$HOME/.ssh/dotfiles-agent/forwarded.sock`. The managed `~/.ssh/rc` hook atomically updates that link to the incoming socket on each forwarded SSH login; shells and command wrappers only select it. Zellij and tmux sessions, the shared popup, and long-running programs all use the same path. A login without forwarding uses the existing selection without replacing it. Local agents, including 1Password, keep their configured paths.

The latest forwarded login selects the agent for every session on that host. If that connection closes, reconnect with forwarding enabled; there is no automatic fallback to another connection. Nested mux shells cannot republish their inherited, stale socket. Missing or invalid incoming sockets produce an error and leave the selected agent unchanged.

## Adopt the stable path in existing programs

Programs started before this change need to inherit the new path once. In an existing remote pane, run:

```sh
fixssh
printf '%s\n' "$SSH_AUTH_SOCK"
# /home/you/.ssh/dotfiles-agent/forwarded.sock
```

Then restart Codex or any other program still holding a raw or session-scoped socket. A child shell cannot change its parent's environment. New programs inherit the stable path, so subsequent reconnects require no environment changes. Existing Zellij servers can still supply an old environment to direct command panes; restart those servers when convenient to normalize their inherited environment too.

The managed Git SSH wrapper also selects the stable path for commands launched by older callers. Old `zellij-*.sock` links are left intact for migration; they are no longer refreshed, and can be removed after their consumers have restarted.

The same workflow forwards the 1Password SSH agent; approve requests locally as usual. Private keys do not need to be copied to the remote host.
