## Shared AI workflows

`ai/skills` and `ai/agents` hold shared instructions. `make claude-shared` links them for Claude. `make codex-skills` exposes skills through `~/.agents/skills/dotfiles`; `make codex-agents` converts shared Markdown agents into Codex TOML definitions. Local entries are preserved.

In Codex, invoke `$socrates Task title` to start a specification dialogue and draft a plan, or `$socrates` to resume a saved session. `$specify` stops at a validated specification, `$critique` reviews it independently, `$verify` evaluates execution evidence, and `$shape` coordinates the complete workflow. Existing `.socrates` sessions and Claude slash commands remain compatible.

Use `$compose` for evidence-backed document development, `$eureka` to capture a breakthrough, and `$stahp` to record a demonstrated dead end. `$reflection` reviews the current conversation and returns findings without changing files or memory. `$handoff` prepares a transcript-backed brief and dispatches a fresh-context subagent; unavailable transcript or dispatch capabilities leave an explicit manual handoff instead of an assumed success.

These workflows and `$skill-authoring` are installed by `make codex-skills`. The [portable package manifest](../ai/skills/portable-workflows.json) selects self-contained packages copied into the managed Codex tree so they survive removal of the source worktree. Other shared skills retain their existing installation behavior. Claude command wrappers read the same canonical skills. The Quarto-specific `/think` command is retired; Quarto authoring remains available through its skill.

For a selective refresh, `bin/sync-codex-skills --only shape` installs the entire portable workflow group, including its companion instructions and shared resources. Selecting a nonportable skill refreshes that skill alone. Selective refreshes preserve all unselected installed entries.

The [Builder guide](./builder.mdx) explains my software development skill: begin with a steel thread, protect retained behavior and expand with proportionate architecture and verification. The [repository bootstrap guide](./repository-bootstrap.md) describes portable Builder, architecture, and PR-writer skills for other repositories.

Agent availability depends on the host. Installing an agent definition does not make delegation available in every conversation surface.

## Platform boundaries

The native OS set is automatic; extra bundles and work contexts are explicit. Some catalog entries configure applications installed separately. Follow the platform reference and plan output instead of assuming every linked configuration also installs its application.
