# Agent worktree launchers

The shell functions in `sh/alias` route `codex` and `claude` through launchers. `command codex` and `command claude` call the native executables directly. Reload the shell aliases after updating dotfiles.

Fresh interactive `codex --worktree` and `codex exec --worktree` requests acquire a named Treehouse branch. `--cd` selects the source checkout and preserves a selected subdirectory in the acquired checkout. The launcher removes the native allocation flag and passes the other arguments through. Ordinary launches, resumes, forks, desktop commands, and remote connections use native behavior.

Claude receives paired `WorktreeCreate` and `WorktreeRemove` factory hooks plus session lifecycle hooks through transient CLI settings. The launcher merges the last effective `--settings` value, preserving caller hooks and settings. CLI, in-session, and subagent worktree requests use Treehouse. A subagent requested from an integration-owned checkout receives its own lease from the primary checkout's pool. Existing tmux notification hooks remain active. Assigned checkouts, including Firstmate checkouts, are reused without claiming their leases.

Missing Treehouse preserves native behavior. An allocation error aborts the launch. Conflicting custom factory hooks or uninspectable plugin/policy sources abort before allocation. Claude modes that disable custom hooks keep native behavior, including `--bare`, `--safe-mode`, `disableAllHooks`, and `allowManagedHooksOnly`.

Treehouse controls its pool, base branch, and committed `.worktreeinclude` manifest. The integration supplies only a unique named branch and lease holder. It keeps private ownership records in `${XDG_STATE_HOME:-~/.local/state}/agent-treehouse`, outside the repository.

The launcher replaces itself with the native client, preserving its streams, signals, and exit status. A detached watcher observes that process's exit. Return is deferred until that process and recorded Claude sessions have ended; missing session startup retains the lease. This keeps subagent leases available after subagent completion and supports tmux children whose allocation identity differs from their actual session identity. The worker checks lease identity, Git registration, branch preservation, conflicts, operations, locks, hidden index flags, dirty files, ignored artifacts, native client inventories, Paseo, and open process references. Only the exact regenerable Codex SessionStart configuration is exempted from ignored-artifact retention. A failed inspection retains the lease. Existing non-pool Codex exit cleanup continues through its original path.

Native Treehouse return uses both lease ID and holder guards and preserves branches and pool directories. The worker repeats its inspections immediately before return. Treehouse 3.1.7 can terminate processes and reset a checkout during return; its CLI has no atomic cleanliness or process-use precondition. A process or write that starts after the final inspection can therefore race return. The integration does not claim atomic protection against that boundary.

Deferred results are recorded in `returns.jsonl` and diagnostics in `worker.log` under the state directory. Results distinguish verified return, retained checkout with a concrete reason, and unconfirmed mutation. There is no startup cleanup sweep. After resolving a retention reason, retry a particular session with `uv run --script ~/.files/bin/agent-treehouse reap SESSION_TOKEN`, using the token in its ownership record or return log. If the ownership record still has `ended: false` because the exit watcher failed, use `watch` instead of `reap` to observe the recorded process's exit first. The worker still performs all guards.

`make test-agent-treehouse` runs one workflow detector per client against native Treehouse, real Git, and process inspection. Native client smoke checks establish the factory payload and settings boundary separately from the simulated agent workflows.
