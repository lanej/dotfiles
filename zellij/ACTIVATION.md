# Zellij activation contract

The native session index and owned Unix sockets establish persistent session IDs and server incarnations. The activation adapter verifies local socket credentials and captures native pane/tab metadata and the full private activation layout. Native pane markers bind layout leaves to exact terminal/plugin IDs; the retained terminal IDs pass through the additive layout wire contract to an allocator that refuses collisions. Application conversation IDs come from their owning native checkpoints.

The installer derives the activation patch from the unchanged curated base, `3235817ccc956b1e17eb66859a758fc8ce10a590`, and records its exact patch hash. Runtime and plugin images live at immutable content-addressed paths. Linux verifies the actual mapped executable; macOS verifies its mapped immutable vnode. The derived server reports hashes of the exact bytes consumed by Wasmi, including cached module and client-clone identities. Owned status/copy-hop plugins also answer a nonce-bound compiled-image/readiness probe targeted at their native plugin ID.

A confirmed checkpoint requires every active application to supply its own checkpoint and one terminal restoration owner. Replacement uses a private supplied layout through the native `--activation-layout` path, preserving the persistent UUID and terminal pane IDs. It consumes each supplied restore argv once and retains uncertain launch/stop outcomes. The terminal's `restored_applications` receipt binds the original process and exact checkpoint session to the one-time wrapper PID/start and the new native process. Installing an image, observing another same-image process, or replaying cached commands cannot substitute for that proof.

Interactive servers launch through an independent user-terminal broker. Start `python3 ~/.files/scripts/zellij-activation.py baseline-serve` from an unaffected terminal shell. Its native ancestry and ownership must verify; the broker inherits that terminal's complete environment directly and records only nonsecret display bindings. Runner environments and serialized full environments are not accepted as baselines. Disposable tests require an explicitly isolated temporary HOME and cannot establish the workstation's baseline.

Ordinary connected user TTY and watcher clients currently lack an operation-bound native reconnect/checkpoint endpoint. They are inventoried and refused before any server stop; their exit followed by manual reattachment does not count as restored connections. Nested attachments also remain intact when their client ownership cannot be fully checkpointed. The supported replacement path requires no connected user clients, confirmed managed application checkpoints, and the verified broker. Generic shells, editors, opaque Codex sessions, and legacy runtimes lacking these native capabilities remain running and report incomplete activation (3).
