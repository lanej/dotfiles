# Pane navigation

This background plugin routes bare Ctrl-h/j/k/l like the tmux configuration: Vim receives the key for internal split navigation, nested tmux/Zellij receives it for its own controls, and other terminal programs yield pane focus to Zellij. Navigation stays in the current tab and does not leave a zoomed pane. Each client gets keys bound to its own plugin instance with `MessagePluginId`, including its client ID in the message; the receiving instance verifies that ID. The plugin queries its own client's focused pane and foreground command, then rechecks the pane and tab before acting. The final check and focus action remain separate server requests.

`python3 scripts/install-zellij-navigation.py` compiles the locked source with Rust 1.95.0 for `wasm32-wasip1` and installs it atomically under `~/.local/share/zellij/plugins/`. Builds reuse the shared Cargo cache. The Zellij tool installer includes this step for all three runtime choices; `make zellij` applies configuration without compiling or installing packages.

Configuration grants this local plugin `ReadApplicationState`, `ChangeApplicationState`, `WriteToStdin`, and `Reconfigure` so it can inspect the foreground pane, change focus, forward editor keys, and register its client's keys. It restores those bindings when configuration reloads, without writing them to disk. The setup helper preserves other cached permission entries. The existing real-terminal navigation workflow consumes the installed artifact and exercises its behavior together with Neovim and the shell integration, including two attached clients.

On the pinned Zellij 0.46.0 runtime, Neovim sends native actions through Unix sockets with generated Lua protobuf bindings. `zellij-context socket` resolves the session's socket and validates its identity once during editor setup; navigation launches no processes. Each API request owns its socket and response, retaining the existing client, pane, tab and zoom checks. A timeout reports uncertainty without replaying a focus change. Unsupported runtimes report a setup warning and retain editor split navigation. Neovim selects Zellij directly from its environment; tmux inside Zellij is outside this integration's supported setup.

Run `uv run scripts/generate-zellij-lua.py` after changing the pinned runtime to regenerate bindings and reference messages from its protobuf definitions. `make test-zellij-navigation` checks generation drift, protobuf compatibility, and the real terminal workflow, including a check that navigation launches no subprocesses. The full generated contract and codec use Neovim’s built-in LuaJIT runtime. The reusable [Lua client and protobuf API](../../nvim/lua/zellij/README.md) are independent of the navigation policy.
